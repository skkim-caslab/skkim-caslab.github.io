About

Memory-centric architecture for LLM inference and vector search

I design hardware that brings computation to where the data lives.

My work makes sparse LLMs run on processing-in-memory, lets vector search stream from DRAM banks, and helps on-device NPUs use every byte of on-chip memory.

LLM decoding and billion-scale vector search are limited by memory bandwidth, not arithmetic. Compression and sparsity should cut that traffic, but their formats rarely match how memory hardware moves data. I co-design data layouts and the hardware that consumes them, so compressed and sparse data streams at full bandwidth.

Research

Bank 0 · PIM

Processing-in-memory for sparse LLMs

Make sparsity something DRAM-bank hardware can actually use.

Commercial bank-level PIM pairs a fixed-function MAC with each DRAM bank, but pruning rarely pays off there: index metadata can outweigh the savings, and the MACs cannot skip zeros. I align pruning with the PIM datapath, using bitmap-indexed contiguous blocks and all-bank-balanced pruning, so sparse weights and KV caches run on the dense pipeline.

BlockPIM · UniPIM · NDPool

Bank 1 · Search

In-memory vector search

Choose a compression format the memory can stream.

Approximate nearest neighbor search behind RAG and vector databases is bandwidth-bound at billion scale. Codebook compression needs lookup-table gathers that bank-level PIM serializes. I encode vectors so distance computation becomes streaming shift-and-add, and study cluster-aware hybrid in-memory execution for billion-scale search.

S-ANNS · CABIN

Bank 2 · Device

On-device LLM accelerators

Manage on-chip memory at runtime, not only at compile time.

Mobile NPUs have a few megabytes of SRAM and low-bandwidth LPDDR, while decoding alternates between compute- and I/O-bound phases. Static compiler tiling cannot follow this. I add lightweight hardware for fine-grained block allocation, preloading into idle bandwidth, and early reclamation.

SMOOTH

Bank 3 · System

Efficient datacenter systems

Carry the same efficiency goals up to the server.

Beyond accelerators, I contribute to system work on shared execution for LLM inference on CXL near-data-processing systems, and on core management that saves energy for latency-critical cloud services.
